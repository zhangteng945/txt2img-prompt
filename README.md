# 大肥鱼 · 文生图提示词工坊

一个**纯静态、零后端**的中文文生图提示词工作台。主流程是把整段中文描述直接交给本机 Ollama 的 `qwen3.5:4b`：模型自己理解、拆成六个中英对照字段，并给出可粘贴的英文负向提示词。哪段中文偏离原意就改哪段，再点「重新生成英文」；英文以你改过的中文为准，不会被偷偷改回初稿。

规则 + 词典仍然保留，但降级为**明确标注的次要选项**：只有你主动点「改用规则生成（次要）」时才走规则路径。模型失败、超时、跨域或返回无效时，页面会清楚报错并保留已有编辑，**不会**自动用词库顶替，再假装这次是模型成功。

- **本机模型主流程**：整体描述 → 六字段中英对照 → 可改中文 → 重新生成英文
- 模型输出的是**逗号分隔的英文生图提示词关键词/短语**，不是把中文整句翻译成英语叙述句；允许 `woman reading a book by a window` 这种绑定动作和位置的短语
- 六个字段：人物与外貌、服装与造型、姿态与动作、场景与背景、光线与镜头、画风与质感
- 中文改动会立刻把对应英文标记为「待更新」；重译成功前不允许生成最终提示词，避免复制过期英文
- 重译只更新待更新字段，并带上原始描述、其余字段当前中英内容作为上下文；中文永远保留用户版本
- 模型失败有具体原因，已有中文、英文和待更新标记都保留；不会静默回退词库
- 「允许模型推测未提示要素」默认关闭；开启后只允许补光线/镜头/画风，并在框上标「补全」，不补身份、剧情、服装
- 搜索、收藏、历史、完整对照预览、复制、待补录反馈继续可用
- 收藏和历史保存中英内容、来源（本地模型/规则）以及每个字段的英文同步状态
- 无需登录、无需构建、不上传内容；只有主动提交整体描述或点「重新生成英文」时才请求你配置的本机/Tailscale Ollama
- 兼容 Lustify Endgame（SDXL）和 ComfyUI
- 手机窄屏可用，复制成功有提示

## 本地打开

最简单的方式：

1. 找到本目录的 `index.html`
2. 双击用现代浏览器打开（Safari / Chrome / Edge 均可）

也可以在本目录启动一个本地静态服务器（可选，不是必需）：

```bash
python3 -m http.server 8000
# 然后打开 http://localhost:8000/
```

项目没有 npm 安装步骤、没有打包步骤，所有脚本都是普通 `<script>`，所以直接以 `file://` 打开也能工作。

## 使用方法

1. 在「整体描述」里写中文，例如：
   > 傍晚街边，短发女人穿米色风衣站着，侧脸看向远处，柔和自然光，电影感
2. 点「用本地模型拆解并翻译」。页面会把描述发给连接设置里的本机 Ollama，由模型自己理解、分解并翻译。
3. 模型返回六个中英对照框后，逐项检查：
   - 人物与外貌
   - 服装与造型
   - 姿态与动作
   - 场景与背景
   - 光线与镜头
   - 画风与质感
4. 哪段中文偏离原意，直接改哪段中文。对应英文会立刻标「英文待更新」。
5. 点「重新生成英文」。页面只重译待更新字段，但会把原始描述、其余字段的当前中文和英文一起交给模型作上下文；重译成功后中文保持你改过的版本，英文才更新。
6. 点「生成正/负提示词」。预览正面、负面英文与中文对照，再复制到 SDXL / ComfyUI。
7. 「预览完整对照」可全屏检查正面 + 负面；预览里也能复制。

### 本地模型主流程

默认就是本地模型；没有「先关闭模型」的开关。连接设置默认：

- API 根地址：`https://macbook-pro.tail349cac.ts.net:11434`（Tailscale Serve，HTTPS，仅尾网）
- 模型：`qwen3.5:4b`
- 请求带 `think:false`、`stream:false`、`format:"json"`
- 页面不保存也不需要密钥；当前 Ollama 没有鉴权

模型请求只包含系统说明和你的整体描述（重译时是当前中文、原始描述和现有英文），**不包含词库**。成功路径的英文只来自模型或你的手改，不会再用 `Translator` 或词库二次改写。

英文表达形态由三处共同约束：初次拆解的系统提示、逐字段重译提示、最终拼装前的防御性清洗。模型返回的是可直接粘贴到 Lustify Endgame（SDXL）/ ComfyUI 的逗号分隔提示词短语，例如 `short-haired woman, white shirt, jeans, reading a book by a window, morning cafe, soft window light`，不是 `A young woman is sitting by the window...` 这样的英语句子翻译。`A scene of` / `This image depicts` / `There is` / `The picture shows` / `In this image` / `A photograph of` 这类叙述套话会被移除；关系、动作对象和否定不会被当作套话删掉。清洗只改变英文形态，不翻译、不读取词库，也不增删用户没说的画质、镜头、身份或剧情。

失败时：

- 超时、网络错误、CORS / HTTP 403、模型没开、返回不是 JSON、字段缺英文、负向提示词不可用、补全标记不合法，都会显示具体错误；
- 已有中文、英文和「英文待更新」标记原样保留；
- **不会**自动运行规则编译器，也不会用词库补写英文；
- 需要规则结果时，自己点「改用规则生成（次要）」。规则结果会在界面和输出里标明「规则次要路径」，不会伪装成模型成功。

「允许模型推测未提示要素」默认关闭。开启后，模型只可以补用户没提到的光线/镜头/画风，并在返回里标 `inferred`；页面在对应框和输出脚注标「补全」。身份、剧情、服装、颜色、动作不允许补。重译不会重新补全。

### 搜索、收藏、历史

- **搜索**：同时搜索内置词库（规则次要路径）、六个框当前内容、收藏和历史。词库结果仍可点「填入…」加入对应框，这是用户主动操作，不是模型失败后的回退。
- **收藏当前**：保存想法、六个框的中英内容、每字段是否待更新、来源、模型名、正负面结果。收藏夹可再次打开。
- **历史**：每次生成后自动保存最近 30 条。历史会显示来源和「英文待更新 N 项」。
- 打开一条本地模型历史时：
  - 中英和同步状态按保存时恢复；
  - 如果保存时就有字段待更新，页面不会自动用词库重译，也不会自动生成最终提示词；会先提示你点「重新生成英文」。
- 收藏与历史保存在浏览器 `localStorage`；清理浏览器数据会丢失。

### 待补录与反馈

- 规则次要路径遇到词库未收录片段时，仍会自动记入本机「待补录」；本地模型路径不查词库，因此不会产生这类记录。
- 可以给每个词写备注、删除单条或清空；打开页面时会按当前词库重新判断，已经能命中的词会标记「词库已可命中，可移除」。
- 「复制补录清单」复制 Markdown + JSON；「下载 JSON」得到 `lexicon-feedback-YYYYMMDD.json`；「在 GitHub 提交反馈」只打开预填好的 issue 页面，不自动提交，也不含 token。
- 数据保存在本机 `localStorage`（`t2i.lexiconFeedback.v1`），不上传。格式见 `feedback/schema.json`，处理流程见 `feedback/README.md`。

## 部署到 GitHub Pages

1. 新建一个 GitHub 仓库，把本目录内容放到**仓库根目录**。
2. 推送到默认分支（例如 `main`）。
3. 打开仓库的 **Settings → Pages**。
4. 在 **Build and deployment** 中选择 **Deploy from a branch**。
5. Branch 选 `main`，目录选 `/ (root)`，保存。
6. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

本仓库当前工作副本**没有 git 仓库，也没有推送或发布 Pages**。所有资源都是相对路径。

## 测试

测试不依赖任何第三方包；本地模型测试全部使用 mock fetch，不要求 Ollama 正在运行：

```bash
node tests/core.test.js
node tests/local-llm.test.js
```

`core.test.js`：规则/词典、六框拆分、补全默认关闭、组装、负面冲突、复杂命中、待补录、结构化场景等，共 36 项。

`local-llm.test.js`：本地模型成功拆解、六字段中英对照、成功路径零 `Translator`/零 `Parser` 调用、请求体不携带词库、think 清理、无效 JSON、缺英文、缺负向提示词、补全默认关闭/开启/非法补全、超时、网络、HTTP 403、中文改动标 stale、重译保留用户中文、只更新待更新字段、重译失败保留编辑、历史兼容、规则路径显式调用，以及初次/重译/最终拼装的英文提示词形态（非叙述句、允许动作短语、关系与否定不丢）等，共 34 项。

本轮另外用临时最小 DOM 冒烟跑过：模型成功填充 → 改中文标待更新 → 重译 → 自动刷新输出 → 模型失败保留编辑并显示错误 → 显式点规则按钮进入次要路径。该临时脚本不随项目发布。真实本机 API 实测见 `REPORT.md` 第 7 节与第 8 节。

## 隐私与边界

- 页面只有在提交整体描述、重新生成英文或显式使用规则路径时才产生网络请求；没有统计脚本、账号或后端。
- 请求只发往你自己填写的 Ollama 地址；不读取、不保存密钥。
- 输入内容只存在于当前页面内；收藏和历史由用户主动使用后写入浏览器 `localStorage`，不会上传。
- 清除浏览器数据会删除本机收藏、历史和待补录。
- 复杂长句、隐喻、方言、冷门专有名词仍可能拆得不够理想；本地模型也可能不完美，所以保留逐字段校对和重译流程。
- 工具不提供内容安全审核，最终提示词及生成结果由使用者自行负责；不宣称覆盖率 99%。

## 自定义

- 调整本地模型：编辑 `js/local-llm.js` 的默认地址、模型名、超时和系统提示词；拆解/重译输出结构、校验和错误分类也在这里。
- 调整六框同步状态：编辑 `js/prompt-flow.js`。
- 增加词条（规则次要路径）：编辑 `js/lexicon.js` 中的 `GROUPS`、`EXTRA_GROUPS`，或 `COVERAGE_GROUPS`。
- 调整规则补全：编辑 `js/complete.js`（默认关闭，需显式传 `{ enabled: true }`）。
- 调整质量词：编辑 `js/assemble.js`（默认不加，需显式传 `{ quality: true }`）。
- 调整负面词：编辑 `js/negative.js`（只服务规则次要路径；本地模型主流程使用模型返回的 negative）。
- 调整界面：`styles.css` 顶部集中定义了颜色、圆角和字体变量。
