# 大肥鱼 · 文生图提示词工坊

一个**纯静态、零后端**的中文文生图提示词工具。输入一句中文（可夹英文），默认用本地词典、规则和模板拆成六个可校对的中英对照框，再按 SDXL / ComfyUI 的习惯组装成可直接粘贴的英文正面与负面提示词。也可以手动打开开关，让本机 Ollama 先做结构化解析；失败会自动退回规则编译器。

- **10,000+ 条中英规范词条**，支持中文/英文/同义词搜索
- 搜索词库、已填框内容、收藏和历史
- 一键收藏当前想法、六个框与最终提示词，可再次打开重新生成
- 自动保存最近 30 条生成历史
- 生成后打开完整中英对照预览，预览里也能复制
- 无需登录、无需构建、默认不联网、不上传内容
- 可选接入本机 Ollama（默认关闭）；开关关闭时零模型请求，失败时自动回退规则
- 直接双击 `index.html` 即可使用
- 兼容 Lustify Endgame（SDXL）和 ComfyUI
- 手机窄屏可用，复制成功有提示

## 本地打开

最简单的方式：

1. 找到本目录的 `index.html`
2. 双击用现代浏览器打开（Safari / Chrome / Edge 均可）

也可以在本目录启动一个本地静态服务器（可选，不是必需）：

```bash
python3 -m http.server 8000
# 然后打开 http://localhost:8000/
```

项目没有 npm 安装步骤、没有打包步骤，所有脚本都是普通 `<script>`，所以直接以 `file://` 打开也能工作。

## 使用方法

1. 在「整体想法」里写中文，例如：
   > 傍晚街边，短发女人穿米色风衣站着，侧脸看向远处，柔和自然光，电影感
2. 点「解析并填入各框」。
3. 检查六个框：
   - 人物与外貌
   - 服装与造型
   - 姿态与动作
   - 场景与背景
   - 光线与镜头
   - 画风与质感
4. 任意修改中文或英文。词典能对齐时会同步另一侧；对不上的原文会保留并给出温和提示。
5. 点「生成提示词」。
6. 复制正面 / 负面英文；下方同时显示中文对照。
7. 点「预览完整对照」可在全屏预览中检查正面 + 负面的完整中英对照，并直接复制。

规则补全默认关闭：不勾选时不会自动加光线、镜头、画风或质量词。需要时可以勾选「允许规则补全（默认关闭）」，补上的内容会显示「补全」标记，并列出中文、英文和原因；修改或删除后标记会自动更新。上方还会显示本轮编出的结构化场景（主体 / 服饰与颜色 / 物体与属性 / 动作 / 关系 / 否定 / 作用范围 / 保留的歧义），六个框由这棵树投影。

### 可选：本机 Ollama 解析

默认关闭，关闭时行为和纯规则版完全一致，不会发任何模型请求。

1. 勾选「使用本地解析模型」。
2. 在「连接设置」里确认 API 根地址和模型名：
   - 默认根地址：`https://macbook-pro.tail349cac.ts.net:11434`（Tailscale Serve，HTTPS，仅尾网）
   - 默认模型：`qwen3.5:4b`
   - 页面不保存也不需要密钥；当前 Ollama 没有鉴权。
3. 点「解析并填入各框」。状态会显示「本地解析中 / 本地解析完成 / 已回退规则」。
4. 模型返回的 JSON 只负责「哪些原文片段 + 槽位 / 角色 / 对象属性 / 关系 / 否定与作用范围 / 例外」；英文仍由 `scene.js`、`translator.js` 的词典和结构模板生成，再走原来的六框投影、`assemble.js` 组装、`negative.js` 负面和 `scene.js` 守恒检查。

回退规则：

- 开关关闭、没有 fetch、地址不是 http(s)：不发请求，直接用规则。
- 超时（默认 50 秒，可中止）、网络错误、CORS / HTTP 403、模型没开、返回不是 JSON、JSON 结构不合法、漏写或改写原文、否定被改成肯定、守恒检查报错：全部自动用规则编译器给出结果，并在状态行写明原因。
- 网络/CORS 失败时会明确提示可能的原因：模型没开、电脑休眠、Tailscale 未连上、Serve 或 CORS 未放行。手机上的 `127.0.0.1` 不是这台 Mac；GitHub Pages 是 HTTPS，也不能请求 `http://127.0.0.1`。
- 开关、根地址和模型名保存在本机 `localStorage`（`t2i.localLLM.v1`）。

### 搜索、收藏、历史

- **搜索**：页面中部的搜索框会同时搜索：
  - 内置词库（中文、英文、同义词）
  - 六个框里当前填写的内容
  - 收藏夹和历史记录
  - 词库结果可以直接点「填入人物与外貌 / 服装与造型…」加入对应框
- **收藏当前**：保存当前想法、六个框、正负面结果和补全标记。收藏会显示在「收藏夹」，可打开、重新生成或删除。
- **历史**：每次生成后自动保存最近 30 条记录，可回看、打开、继续编辑和删除。
- 收藏与历史保存在浏览器 `localStorage`；清理浏览器数据会丢失。若浏览器禁用本地存储，功能仍可在本次页面中使用，并会给出提示。

### 待补录与反馈

- 每次拆解想法或生成提示词时，未收录片段会自动记入本机「待补录」；同一词去重并累计次数，保留最近 5 条完整想法原文、可能所在框和时间。
- 搜索行「待补录」按钮显示数量；未收录警告条里也能直接打开。
- 可以给每个词写备注（大概意思 / 想译成什么英文 / 属于哪一类）、删除单条或清空；打开页面时会按当前词库重新判断，已经能命中的词会标记「词库已可命中，可移除」。
- 「复制补录清单」复制结构化 Markdown + JSON；「下载 JSON」得到 `lexicon-feedback-YYYYMMDD.json`；「在 GitHub 提交反馈」只打开预填好的 `issues/new`，不会自动建 issue，也不含 token。
- 数据保存在本机 `localStorage`（`t2i.lexiconFeedback.v1`），不会上传；格式见 `feedback/schema.json`，处理流程见 `feedback/README.md` 与 `BRIEF-process-feedback.md`。

## 部署到 GitHub Pages

当前不需要真的创建仓库，但以后可以直接这样上线：

1. 新建一个 GitHub 仓库，把本目录内容放到**仓库根目录**。
2. 推送到默认分支（例如 `main`）。
3. 打开仓库的 **Settings → Pages**。
4. 在 **Build and deployment** 中选择 **Deploy from a branch**。
5. Branch 选 `main`，目录选 `/ (root)`，保存。
6. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

如果希望把站点放在 `/docs` 目录，把 `index.html`、`styles.css`、`js/` 整体移入 `docs/`，然后在 Pages 里选择 `/docs` 即可。所有资源都是相对路径，两种方式都能用。

仓库里的 `logs/` 是开发日志，已加入 `.gitignore`，不需要发布。

## 词典与算法

词典规模（当前版本）：

- **14,482 条规范词条**
- **8,433 条人工词条**
- **6,049 条组合词条**
- **26,665 个中文说法 / 同义词**
- **20,838 个英文说法 / 同义词**
- **27 个类别**（含 `body` 身体部位）
- `action` 行为动作 **344 条**、`sign` 告示标识 **163 条**、`body` 身体部位 **19 条**
- object 物体道具（含常用局部）**2,963 条**

这版继续按「覆盖率最佳点」修正：目标约 **10,000–15,000 条有效独立概念**，优先补场景、姿态、人物身份、外貌、表情、光线、镜头、画风，以及本轮加厚的日常动作、物体、动物和氛围。颜色 × 服装不再做全量笛卡尔积，改成每件核心单品只配它常见的颜色；鞋履、配饰、材质、图案也只保留常用搭配。当前 14,482 条仍在目标区间内；object 已从 346 条补到 2,963 条，补的是按生活场景整理的独立物体和真实局部，而不是把低价值颜色组合重新堆回来。本轮另外把日常行为/动宾短语独立成 `action`（344 条），把「禁止 / 请勿 / 严禁 / 不准 / 小心 / 注意」类公共标识独立成 `sign`（163 条）；标识整条优先保留，不因内部含「拍照 / 奔跑」等动作词被拆碎。

高频匹配优先：`美女 → beautiful woman`、`帅哥 / 美男 → handsome man`、`美少女 → beautiful girl`、`漂亮 → pretty`、`美丽 → beautiful`、`好看 → good-looking`、`handsome / pretty / beautiful / gorgeous / attractive / stunning` 均有独立规范词或宽别名；`佳人`、`女神`、`校花`、`校草`、`handsome boy` 等同类口语也一并覆盖。「美女」指向「美丽的女性」，「美少女」单独成条，不会误绑到「混血女性」这类窄词。

关系组装优先：先按「谁 + 对什么 + 做什么 + 什么氛围」拆出主体、动作、目标物体和氛围零件，再按「给……上 / 对着 / 在……上 / 在……旁 / 在……下 / 在……后 / 在……之间 / 从……跳到 / 把……放在 / 沿着 / 穿过」等关系拼成自然英文。动作 + 地点的关系句会拆成两框：动作留在姿态框，方位短语进场景框，最终仍粘回 `walking on the beach`；例如「走在沙滩上」→ 姿态 `walking` + 场景 `on the beach`。例如「小狗给车轮上撒尿的搞笑画面」会拆成 `a dog` + `peeing on a car wheel` + `funny scene`；换成电线杆、树或消防栓，仍然复用同一套主体、动作和关系，而不是给每句笑话单独写整句词条。动作（吃、喝、拿、抱、扔、推、拉、坐、躺、蹲、跪、跑、跳、爬、躲、打、踢、拍、摸、指、看、听、说、睡、排队、开门、洗手、做饭、打电话、拍照、看书、写字、画画、弹琴、骑车、开车、上下车、拥抱、亲吻、挥手、鞠躬、吵架、打架，以及动物嗅、舔、咬、抓、摇尾巴、卧、飞、游等）、物体（家具、餐具、家电、文具、玩具、运动器材、食物饮品、植物、街边设施、交通工具及局部、建筑局部等）和氛围（搞笑、温馨、治愈、紧张、恐怖、浪漫、日常、纪实、夸张、荒诞、电影感等）都是可组合的独立零件。仍不宣称已经覆盖 99%，生僻词和长尾说法继续按「补零件 / alias，再补必要关系句式」处理。

组合生成只保留这些范围：

- 颜色 × 核心服装（按单品配色，375 条）
- 颜色 × 少量鞋履 / 配饰（159 + 192 条）
- 材质 × 适配单品（92 条）、图案 × 适配单品（60 条）
- 常见发色 × 高频发型（300 条）
- 时间 / 天气 × 常用场景（3,465 + 1,111 条）
- 光质 × 光型（255 条）、焦距 × 景别（40 条）

生成时跳过已有规范词、同义说法和重复英文，跳过「皮革皮夹克」「牛仔牛仔裙」这类重复语义，也过滤「晴天的星空」这类矛盾组合。英文只使用已有规范译法，不引入机器翻译。

词典按人物类型与年龄体态、五官外貌、发型发色、眼睛、表情、妆容、服装、配饰、鞋履、材质、图案、颜色、姿态动作、行为动作、告示标识、场景、时间、天气、光线、镜头构图、画风、质感、质量词、负面词等类别组织。同义词指向同一个规范译法，英文尽量采用生图提示词惯用表达（如 `cinematic lighting`、`soft natural light`、`film grain`、`50mm`、`shallow depth of field`）。

处理流程：

1. **切句 / 候选切分**：中文标点、英文逗号、顿号、换行作为边界；转折词也作为子句边界。对每个位置建立词典长词、结构标记和未知字候选边，用动态规划保留前几条路径；仍有多种解释时保留歧义备选。
2. **编结构化场景**：先把句子编成主体、属性、服饰、物体、动作、关系、否定、作用范围与例外。颜色绑定到最近的名词对象（红→衣服、蓝→汽车、白→房子），远处只作为该物体的距离属性。
3. **投影六个框**：人物框只放主体与外貌，服饰进服装框，动作进姿态框，地点进场景框；整句动作不会粘在人物框。
4. **中英同树生成**：中英都从同一结构投影，服装关系拼成 `a girl wearing a white dress, standing under a cherry blossom tree`，不是拆散的标签。
5. **补全**：默认关闭；用户勾选后才在缺失维度补光线/镜头/画风并逐条记录。
6. **组装**：人物 → 服装关系 → 姿态 → 场景 → 光线镜头 → 画风；质量词默认不加。
7. **语义守恒检查**：检查否定是否泄漏到正面、颜色是否错绑、关系是否丢失、未识别内容是否残留、是否擅自补光/补镜头/补画风；不通过时明确标为不完整。
8. **负面**：通用负面词 + 本轮否定/作用范围计划；局部否定抑制全局词，例外作用域加入保护项，并根据正面明确要求避让冲突。

## 隐私与边界

- 页面默认没有网络请求，没有统计脚本，没有账号，没有后端。只有两种情况会联网：你打开「使用本地解析模型」并主动解析时，页面请求你自己填写的本机/Tailscale Ollama 地址；你主动点「在 GitHub 提交反馈」时，浏览器打开外部 issue 页面。
- 输入内容默认只存在于当前页面内；收藏和历史由用户主动使用「收藏当前」或「生成提示词」后写入浏览器本地 `localStorage`，不会上传。
- 清除浏览器数据会删除本机收藏和历史。
- 默认是**规则 + 词典**工具；只有手动打开开关时才会用本机小模型做结构化解析。复杂长句、隐喻、方言、冷门专有名词仍可能拆得不够理想，模型结果也会被逐段校验，漏写或改写就回退规则。这类词会保留原文并提示，不会瞎编错译。
- 10,000+ 条词条以场景、人物、姿态、外貌、光线、镜头和画风等独立概念为主，组合只保留常用搭配；极冷门的现实品牌、特定历史装备、亚文化服饰或虚构角色仍需自行补词。
- 补全默认关闭；只有用户勾选「允许规则补全」时才补光线/镜头/画风，且不会编造人物身份、服装、伤势或剧情。
- 工具不提供内容安全审核，最终提示词及生成结果由使用者自行负责。

## 自定义

- 增加词条：编辑 `js/lexicon.js` 中的 `GROUPS`、`EXTRA_GROUPS`，或 `COVERAGE_GROUPS`（紧凑格式 `中文|英文|中文别名|英文别名`）。
- 调整组合：编辑 `COLOR_ZH`、`GARMENT_COLOR_ZH`、`MATERIAL_GARMENTS_ZH`、`PATTERN_GARMENTS_ZH`、`TIME_ZH`、`SCENE_ZH` 等数组，并保持 `addGenerated` 的去重与过滤规则。
- 调整默认补全：编辑 `js/complete.js`（默认关闭，需显式传 `{ enabled: true }`）。
- 调整质量词：编辑 `js/assemble.js`（默认不加，需显式传 `{ quality: true }`）。
- 调整负面词顺序与冲突规则：编辑 `js/negative.js`。
- 调整本地模型：编辑 `js/local-llm.js` 的默认地址、模型名、超时和系统提示词；解析结果映射到场景树的部分在 `js/scene.js` 的 `fromSpec`。
- 调整界面：`styles.css` 顶部集中定义了颜色、圆角和字体变量。
